# Case Study

Network traffic analysis is an important part of cybersecurity monitoring and incident investigation. Network packets can provide valuable information about communication between hosts, protocols being used, source and destination addresses, ports, and potential abnormal activities.

In this case study, network traffic is analyzed to understand normal communication patterns and identify potential indicators of suspicious or malicious activity.

# Objective

The objectives of this analysis are to:

Identify source and destination hosts.
Identify protocols and commonly used ports.
Analyze communication patterns between hosts.
Identify unusual or potentially suspicious traffic.
Investigate indicators that may represent security incidents.
Document findings and provide appropriate recommendations.

# Scenario

When attempting to access the website, the same connectivity error was observed.
During packet capture, the network traffic showed communication between the local host and the DNS server. The DNS request was sent using UDP, followed by an ICMP error response indicating:
UDP port 53 unreachable
This observation indicates that the DNS request could not reach a service listening on UDP port 53.

In this scenario, network traffic recorded in Wazuh is analyzed to identify communication activities within a specific time period.

The investigation begins by adjusting the time display and then applying protocol-based filtering to narrow down the traffic relevant to the analysis.

## Time Display

The Time Display is changed from UTC to Date and Time of Day.

This adjustment makes event timestamps easier to interpret during the investigation and allows analysts to perform filtering based on the actual date and time when the network activity occurred.

Purpose:

Identify the exact time of network activity.
Filter events based on a specific date and time range.
Build a clearer incident timeline.
Support real-time incident analysis and event correlation.

By using a readable date and time format, analysts can more easily determine when a specific network event occurred and correlate it with other security events.

## Conversation Filter

After adjusting the time display, the Conversation Filter is used to filter network traffic based on the communication protocol.

The filter can be used to analyze different protocols, including:

Ethernet
TCP
IPv4
Other available network protocols

For this case study, the analysis focuses on:

Protocol: IPv4

The IPv4 filter is selected to narrow the investigation to IPv4-based network communication, allowing the analyst to focus specifically on traffic relevant to the network layer.

## Analysis Flow

The investigation process can be summarized as:

Wazuh Network Traffic → Time Display → Date & Time Filtering → Conversation Filter → IPv4 Traffic → Network Traffic Analysis

This filtering approach allows the analyst to focus on IPv4 communication within a specific time period and examine the resulting network activity more efficiently.

## Expected Result

Through this analysis, the security analyst is expected to be able to:

Identify when network activities occurred based on event timestamps.
Filter network events according to a specific date and time range.
Filter traffic based on the communication protocol.
Focus the investigation on IPv4 network communication.
Identify unusual or potentially suspicious network communication patterns.
Use the analysis results to support security incident investigation and network security monitoring.

## Conclusion

Network traffic analysis using wireshark provides a structured approach to monitoring and investigating network communication.

Changing the Time Display from UTC to Date and Time of Day makes it easier to analyze events based on the actual incident timeline, while the Conversation Filter allows analysts to narrow down traffic based on specific protocols.

In this case study, the IPv4 filter is used to focus the investigation on IPv4 communication, providing a more targeted analysis of network layer traffic and supporting the identification of potentially suspicious network activities.
